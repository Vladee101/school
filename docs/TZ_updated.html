1. Общие сведения

1.1. Назначение системы

Разрабатывается информационный веб-портал школы с профориентационной функциональностью для учеников, учителей и администрации.

Основная профориентационная функция системы — прохождение учащимися диагностического теста ДДО Климова с последующим определением профессиональной направленности и отображением результатов.

1.2. Основные возможности

  • публичный просмотр новостей школы;
  • публичный просмотр и скачивание документов в формате PDF;
  • просмотр расписания по классам;
  • просмотр общей информации о школе;
  • авторизация пользователей;
  • разграничение доступа по ролям;
  • прохождение теста ДДО Климова;
  • просмотр учеником собственных результатов;
  • просмотр учителем результатов учеников назначенных классов;
  • формирование сводной статистики по классу;
  • администрирование пользователей, классов, новостей, документов и справочника профессий.
Важно: в системе предусмотрены только три роли: ученик, учитель и администратор. Отдельной роли «куратор» нет.

2. Роли пользователей

В системе используются следующие роли:

student — Ученик teacher — Учитель admin — Администратор
Роль Основные возможности
Ученик Проходит тест, просматривает собственные результаты, пользуется публичной частью сайта.
Учитель Имеет весь функционал бывшего куратора: просматривает назначенные классы, учеников, статусы прохождения теста, последние результаты и сводную статистику.
Администратор Управляет пользователями, классами, новостями, документами и справочником профессий.
Учитель не получает права администратора и не может управлять пользователями, тестом или результатами.

3. Фича 1 — Публичная часть портала

User Story

Как посетитель сайта — родитель, ученик, сотрудник школы или гость — я хочу просматривать новости, документы, расписание и информацию о школе без авторизации.

FT-1.1. Новости

  • Новости доступны неавторизованным пользователям.
  • Пользователь видит список опубликованных новостей.
  • Новости сортируются от новых к старым.
  • Для сортировки используется дата публикации published_at.
  • Каждая новость содержит заголовок, дату публикации и краткое описание.
  • При открытии новости пользователь видит полный текст.
  • Черновики не отображаются публично.

FT-1.2. Документы

  • Документы доступны неавторизованным пользователям.
  • Документы предоставляются только в формате PDF.
  • Пользователь может открыть или скачать опубликованный PDF.
  • Черновики документов не отображаются публично.
  • Для документа отображаются название, категория и дата.

FT-1.3. Расписание

  • Пользователь может выбрать класс.
  • После выбора класса отображается актуальное расписание.
  • Расписание должно быть связано с учебным периодом.
  • В MVP допускается наличие одного актуального расписания для класса.
  • Структура должна позволять в дальнейшем хранить расписания разных учебных периодов.

FT-1.4. Информация о школе

  • адрес школы;
  • контактная информация;
  • общая информация о школе;
  • другая статическая информация, необходимая для дипломного проекта.

FT-1.5. Доступ

Публичная часть доступна без авторизации.

4. Фича 2 — Авторизация и разграничение доступа

FT-2.1. Создание пользователей

Самостоятельная регистрация пользователей не предусмотрена. Учетные записи создаются администратором.

FT-2.2. Первый вход

  • При создании пользователя администратор задаёт временный пароль.
  • При первом входе пользователь обязан изменить пароль.
  • Временный пароль не хранится в открытом виде.
  • После изменения пароля флаг must_change_password сбрасывается.

FT-2.3. Вход

  • Вход выполняется по логину и паролю.
  • Неактивный пользователь не может авторизоваться.
  • После выхода пользовательская сессия завершается.
  • Пароли хранятся только в виде криптографического хэша.

FT-2.4. Ограничение доступа

Функция Гость Ученик Учитель Администратор
Новости Да Да Да Да
Документы PDF Да Да Да Да
Расписание Да Да Да Да
Прохождение теста Нет Да Нет Нет
Свои результаты Нет Да Нет Нет
Результаты учеников Нет Нет Да, только своих классов Да
Управление пользователями Нет Нет Нет Да

Ограничения доступа должны проверяться на серверной стороне/API, а не только скрытием элементов интерфейса.

5. Фича 3 — Профориентационный тест ДДО Климова

FT-3.1. Общие сведения

В системе реализуется тест дифференциально-диагностического опросника (ДДО) Климова.

Тест состоит из 20 пар утверждений. В каждой паре ученик обязан выбрать ровно один вариант: А или Б.

FT-3.2. Пять типов профессиональной направленности

  1. Человек — природа (Ч-П)
  2. Человек — техника (Ч-Т)
  3. Человек — человек (Ч-Ч)
  4. Человек — знаковая система (Ч-З)
  5. Человек — художественный образ (Ч-ХО)

FT-3.3. Правила прохождения

  • Все 20 вопросов отображаются пользователю.
  • В каждой паре можно выбрать только один вариант.
  • Нельзя завершить тест, если не отвечен хотя бы один вопрос.
  • До завершения теста результат не сохраняется в БД.
  • При выходе из теста до завершения прохождение считается незавершённым.
  • При повторном запуске незавершённый тест начинается заново.
  • Промежуточные ответы не должны восстанавливаться после выхода.

FT-3.4. Сохранение результата

Результат создаётся в базе данных только после полного ответа на все 20 пар и подтверждения завершения теста.

Каждое завершённое прохождение создаёт новый результат. Предыдущие результаты не изменяются.

FT-3.5. Алгоритм подсчёта

Каждый выбранный вариант соответствует одной из пяти шкал. За каждый выбор начисляется 1 балл соответствующему типу.

Поскольку в тесте 20 пар, сумма пяти итоговых шкал всегда должна быть равна 20: 

score_chp + score_cht + score_chch + score_chz + score_chho = 20

FT-3.6. Фиксированный ключ теста

В MVP вопросы и ключ теста являются фиксированной частью системы. Администратор не может редактировать вопросы, варианты ответов или соответствие вариантов шкалам.

Тип Вопросы / варианты
Человек — природа 1А, 3Б, 6А, 10А, 11А, 13Б, 16А, 20А
Человек — техника 1Б, 4А, 7Б, 9А, 11Б, 14А, 17Б, 19А
Человек — человек 2А, 4Б, 6Б, 8А, 12А, 14Б, 16Б, 18А
Человек — знаковая система 2Б, 5А, 9Б, 10Б, 12Б, 15Б, 19Б, 20Б
Человек — художественный образ 3А, 5Б, 7А, 8Б, 13А, 15А, 17А, 18Б
Данный ключ является фиксированной версией методики для дипломного проекта. Администратор не должен иметь возможности изменять его через интерфейс.

FT-3.7. Определение доминирующего типа

После подсчёта баллов определяется максимальное значение среди пяти шкал.

Если максимальное значение имеет один тип, он считается доминирующим.

Если максимальное значение имеют два или более типа, все они считаются доминирующими и должны отображаться пользователю.

Нельзя искусственно выбирать один тип при одинаковом максимальном результате.

FT-3.8. Результат ученика

После завершения теста ученик видит:

  • дату прохождения;
  • баллы по всем пяти направлениям;
  • доминирующий тип или несколько доминирующих типов;
  • описание соответствующих профессиональных направлений;
  • рекомендуемые профессии.

FT-3.9. История результатов

  • Все завершённые прохождения сохраняются.
  • Новое прохождение не перезаписывает старое.
  • Ученик видит только свои результаты.
  • Результат после сохранения не редактируется.
  • Результат после сохранения не пересчитывается.

7. Фича 4 — Личный кабинет ученика

FT-4.1. Главная страница кабинета

После авторизации ученик попадает в личный кабинет.

В кабинете отображаются:

  • ФИО ученика;
  • класс;
  • информация о прохождении теста;
  • последний завершённый результат;
  • история завершённых результатов.

FT-4.2. Прохождение теста

  • Ученик может начать новый тест.
  • Тест состоит из 20 пар.
  • На каждом вопросе выбирается один вариант.
  • Можно перемещаться между вопросами.
  • Перед завершением система проверяет наличие ответов на все 20 вопросов.
  • После завершения рассчитывается и сохраняется результат.

FT-4.3. Просмотр результатов

Ученик может просматривать только собственные завершённые результаты.

Доступ к результатам других учеников запрещён.

8. Фича 5 — Панель учителя

Учитель полностью заменяет ранее предусмотренную роль «куратор». Весь функционал куратора сохраняется за учителем.

FT-5.1. Классы

  • Учитель видит назначенные ему классы.
  • Один класс в MVP имеет одного назначенного учителя.
  • Один учитель может вести несколько классов.
  • Учитель не видит классы, которые ему не назначены.

FT-5.2. Список учеников

При выборе класса учитель видит список учеников данного класса.

Для каждого ученика отображается:

  • ФИО;
  • статус прохождения теста;
  • дата последнего завершённого прохождения;
  • последний доминирующий тип или типы.

FT-5.3. Последний результат

Если ученик проходил тест несколько раз, в основной сводке класса используется его последний завершённый результат.

Учитель при необходимости может просмотреть историю завершённых результатов ученика в пределах доступного ему класса.

FT-5.4. Сводная статистика

Панель учителя содержит сводную статистику по ученикам выбранного класса.

Например:

  • количество учеников;
  • количество прошедших тест;
  • количество учеников без результата;
  • распределение учеников по типам профессиональной направленности.

FT-5.5. Фильтрация

Учитель может фильтровать список учеников по типу профессиональной направленности.

При наличии нескольких доминирующих типов ученик должен попадать в каждый соответствующий фильтр.

FT-5.6. Ограничения учителя

  • не может создавать пользователей;
  • не может удалять пользователей;
  • не может изменять роли пользователей;
  • не может редактировать вопросы теста;
  • не может изменять ключ теста;
  • не может изменять сохранённые результаты;
  • не может просматривать данные чужих классов.

9. Фича 6 — Панель администратора

FT-6.1. Пользователи

Администратор может:

  • создавать пользователей;
  • редактировать пользователей;
  • активировать и деактивировать пользователей;
  • назначать роль;
  • назначать ученика классу;
  • назначать учителя классу;
  • сбрасывать пароль пользователя.

Доступные роли при создании пользователя: student, teacher, admin.

FT-6.2. Классы

Администратор может:

  • создавать классы;
  • редактировать классы;
  • назначать учителя классу;
  • добавлять учеников в класс;
  • удалять ученика из класса.

FT-6.3. Новости

Администратор может:

  • создавать новости;
  • редактировать новости;
  • публиковать новости;
  • снимать новости с публикации;
  • удалять новости.

FT-6.4. Документы

Администратор может:

  • загружать PDF-документы;
  • редактировать название и категорию;
  • публиковать документ;
  • снимать документ с публикации;
  • удалять документ.
Загрузка файлов других форматов в MVP не предусматривается. Разрешён только PDF.

FT-6.5. Справочник профессий

Администратор может:

  • создавать профессии;
  • редактировать профессии;
  • деактивировать профессии;
  • редактировать описания пяти профессиональных направлений.

FT-6.6. Тест Климова

Администратор НЕ может редактировать тест.

Администратору запрещено изменять:

  • текст вопросов;
  • варианты А/Б;
  • количество вопросов;
  • ключ соответствия вариантов шкалам;
  • алгоритм расчёта;
  • сохранённые результаты учеников.

Вопросы и ключ теста являются фиксированной конфигурацией системы, загруженной разработчиком.

10. Механизм создания пользователей

10.1. Создание ученика

Администратор указывает:

  • ФИО;
  • логин;
  • временный пароль;
  • класс.

Роль автоматически устанавливается как student.

10.2. Создание учителя

Администратор указывает:

  • ФИО;
  • логин;
  • временный пароль.

Роль устанавливается как teacher. Назначение учителя классу выполняется отдельно.

10.3. Создание администратора

Учетная запись администратора создаётся администратором системы согласно предусмотренной процедуре развёртывания.

10.4. Защита от самостоятельного создания аккаунтов

Поскольку публичной регистрации нет, пользователь не может самостоятельно создать учетную запись в системе.

Это исключает появление пользовательских аккаунтов через стандартную форму регистрации.

12. Связи сущностей

Пользователь │ ├── 1:N ── Результат теста │ │ │ └── 1:N ── Ответ ученика │ ├── N:M ── Класс │ через Ученик-Класс │ └── 1:N ── Класс как назначенный учитель Тест │ └── 1:N ── Вопрос │ └── 1:N ── Ответ ученика Результат теста │ └── dominant_type │ └── Тип профессиональной направленности │ └── 1:N ── Профессия Класс │ └── 1:N ── Расписание

Основные ограничения связей

  • ученик может состоять в классе;
  • один класс имеет одного назначенного учителя в MVP;
  • один учитель может быть назначен нескольким классам;
  • учитель видит только назначенные ему классы;
  • ученик видит только собственные результаты;
  • один результат содержит ответы на все 20 вопросов;
  • незавершённый результат не существует в базе данных.

13. Безопасность и права доступа

13.1. Пароли

  • пароли не хранятся в открытом виде;
  • используется криптографический хэш;
  • временный пароль не сохраняется в открытом виде;
  • после первого входа требуется смена временного пароля.

13.2. API

Все проверки прав доступа должны выполняться на серверной стороне.

Нельзя считать достаточной защитой простое скрытие кнопки или страницы в интерфейсе.

13.3. Защита результатов

  • ученик не может запросить результат другого ученика через API;
  • учитель не может получить результаты учеников чужого класса;
  • администратор имеет административный доступ согласно своей роли;
  • результат после сохранения не может быть изменён через пользовательский интерфейс.

13.4. Сессия

  • неавторизованный пользователь не получает доступ к закрытым разделам;
  • при выходе сессия завершается;
  • проверка авторизации выполняется на сервере.

14. Адаптивность

Сайт должен корректно работать на персональных компьютерах, ноутбуках, планшетах и смартфонах.

14.1. Требования

  • адаптивная вёрстка;
  • мобильное меню;
  • отсутствие горизонтальной прокрутки всей страницы;
  • адаптация таблиц под небольшие экраны;
  • адаптация графиков и диаграмм;
  • корректное отображение личного кабинета;
  • корректное отображение панели учителя;
  • корректное отображение административной панели;
  • крупные кликабельные варианты ответа в тесте;
  • удобное прохождение теста на смартфоне.

14.2. Минимальные устройства

  • Desktop;
  • ноутбук;
  • планшет;
  • смартфон.

15. Нефункциональные требования

15.1. Производительность

Основные страницы системы должны загружаться не более чем за 3 секунды при штатной нагрузке и нормальном интернет-соединении.

15.2. Совместимость

Система должна корректно работать в актуальных версиях:

  • Google Chrome;
  • Mozilla Firefox;
  • Microsoft Edge;
  • Safari.

15.3. Удобство использования

  • интерфейс должен быть понятен без специального обучения;
  • основные действия должны быть доступны через понятные элементы управления;
  • ошибки пользователя должны сопровождаться понятными сообщениями;
  • форма прохождения теста должна быть удобна на мобильных устройствах.

15.4. Целостность данных

  • результат теста сохраняется атомарно после завершения;
  • для результата должно существовать 20 ответов;
  • сумма пяти шкал должна быть равна 20;
  • нельзя изменить результат после сохранения.

16. Критерии приёмки

AC-1. Публичная часть

  • AC-1.1 — неавторизованный пользователь может открыть новости.
  • AC-1.2 — новости отсортированы от новых к старым.
  • AC-1.3 — пользователь может открыть полный текст новости.
  • AC-1.4 — неавторизованный пользователь может скачать опубликованный PDF.
  • AC-1.5 — черновые новости не отображаются публично.
  • AC-1.6 — черновые документы не отображаются публично.
  • AC-1.7 — пользователь может посмотреть расписание выбранного класса.

AC-2. Авторизация

  • AC-2.1 — самостоятельная регистрация отсутствует.
  • AC-2.2 — пользователь может войти по выданному логину и паролю.
  • AC-2.3 — при первом входе требуется смена временного пароля.
  • AC-2.4 — заблокированный пользователь не может войти.
  • AC-2.5 — после выхода сессия завершается.
  • AC-2.6 — права доступа проверяются на сервере.

  • AC-3.1 — тест содержит ровно 20 пар.
  • AC-3.2 — в каждой паре можно выбрать только один вариант.
  • AC-3.3 — нельзя завершить тест при наличии неотвеченных вопросов.
  • AC-3.4 — незавершённый тест не сохраняется.
  • AC-3.5 — после выхода незавершённое прохождение начинается заново.
  • AC-3.6 — после завершения создаётся новый результат.
  • AC-3.7 — повторное прохождение не изменяет предыдущий результат.
  • AC-3.8 — сумма пяти шкал равна 20.

  • AC-3.10 — при одном максимальном результате определяется один доминирующий тип.
  • AC-3.11 — при нескольких одинаковых максимумах отображаются все доминирующие типы.

  • AC-3.13 — сохранённый результат нельзя редактировать.
  • AC-3.14 — администратор не может изменять вопросы и ключ теста.

17. Тест Климова — техническая реализация

17.1. Источник теста

В проекте используется фиксированный вариант ДДО Климова, состоящий из 20 пар утверждений.

Тексты вопросов и ключ должны быть заранее внесены в базу данных при первоначальном наполнении системы.

17.2. Пример структуры вопроса

{
    "question_number": 1,
    "option_a": "Вариант А",
    "option_b": "Вариант Б",
    "scale_a": "CH_P",
    "scale_b": "CH_T"
}

17.3. Пример результата

{
    "score_chp": 6,
    "score_cht": 4,
    "score_chch": 3,
    "score_chz": 4,
    "score_chho": 3,
    "dominant_type": ["CH_P"]
}

В данном примере доминирующим является тип «Человек — природа».

17.4. Пример равного максимума

{
    "score_chp": 6,
    "score_cht": 2,
    "score_chch": 6,
    "score_chz": 3,
    "score_chho": 3,
    "dominant_type": ["CH_P", "CH_CH"]
}

В случае равенства максимальных значений система отображает оба доминирующих направления.

18. Ограничения MVP

В первую версию проекта не входят:

  • самостоятельная регистрация пользователей;
  • восстановление пароля через email;
  • массовый импорт пользователей;
  • редактор тестов;
  • создание собственных тестов администратором;
  • изменение ключа теста через интерфейс;
  • сохранение незавершённых прохождений;
  • редактирование сохранённых результатов;
  • мобильное приложение;
  • сложная система уведомлений;
  • несколько разных профориентационных тестов.
Единственный профориентационный тест MVP — ДДО Климова.

19. Основные пользовательские сценарии

19.1. Ученик проходит тест

  1. Ученик авторизуется.
  2. Открывает личный кабинет.
  3. Нажимает «Пройти тест».
  4. Система показывает 20 пар.
  5. Ученик выбирает по одному варианту в каждой паре.
  6. Нажимает «Завершить тест».
  7. Система проверяет заполнение всех вопросов.
  8. Система рассчитывает пять шкал.
  9. Система определяет один или несколько максимальных типов.
  10. Создаётся новый результат.
  11. Сохраняются ответы и итоговые баллы.
  12. Ученик видит результат.

19.2. Ученик вышел до завершения

  1. Ученик начал тест.
  2. Ответил только на часть вопросов.
  3. Вышел из теста.
  4. Незавершённое прохождение не сохраняется.
  5. При следующем запуске ученик начинает тест заново.

19.3. Учитель просматривает класс

  1. Учитель авторизуется.
  2. Открывает панель учителя.
  3. Выбирает назначенный класс.
  4. Видит список учеников.
  5. Видит статус прохождения.
  6. Видит последний завершённый результат.
  7. Может фильтровать учеников по типу направленности.
  8. Видит сводную статистику класса.

19.4. Администратор создаёт ученика

  1. Администратор открывает управление пользователями.
  2. Нажимает «Создать пользователя».
  3. Указывает ФИО.
  4. Указывает логин.
  5. Задаёт временный пароль.
  6. Выбирает класс.
  7. Система создаёт пользователя с ролью student.
  8. Устанавливается must_change_password = true.

21. Итоговые правила системы

  1. В системе существует три роли: ученик, учитель, администратор.
  2. Роль «куратор» отсутствует. Весь её функционал передан роли учителя.
  3. Самостоятельной регистрации пользователей нет.
  4. Первый вход выполняется по временному паролю с обязательной сменой пароля.
  5. Новости доступны обычному неавторизованному пользователю.
  6. Публично отображаются только опубликованные новости и документы.
  7. Документы в MVP имеют только формат PDF.
  8. Тест Климова состоит ровно из 20 пар.
  9. В каждой паре выбирается ровно один вариант.
  10. Незавершённое прохождение не сохраняется.
  11. Результат сохраняется только после полного завершения теста.
  12. Каждое повторное завершённое прохождение создаёт новый результат.
  13. Результаты после сохранения не редактируются и не пересчитываются.
  14. При равенстве максимальных баллов отображаются все соответствующие доминирующие типы.
  15. Ученик видит только собственные результаты.
  16. Учитель видит только назначенные ему классы и их учеников.
  17. В сводке учителя используется последний завершённый результат ученика.
  18. Администратор не редактирует вопросы, варианты ответов и ключ теста Климова.
  19. Администратор может управлять справочником профессий и описаниями профессиональных направлений.
  20. Сайт должен быть адаптивным и удобным для использования на смартфонах, планшетах и компьютерах.
