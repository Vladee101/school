# 0010. Разделы просмотра расписания для ученика и учителя (UC-01–UC-03)

Дата: 2026-11-05. Источник требования: `Use_Cases_Расписание_школьного_портала.pdf`
(модуль «Расписание занятий»: UC-01–UC-03, BR-01–BR-06, 6 критериев готовности).

## Контекст

Администратор уже ведёт расписание классов (`/admin/classes/[id]/schedule`); данные хранятся в
`schedule_entries` (день недели, номер урока, предмет, `teacher_name` — текст, кабинет). Ученик
привязан к классу (`student_classes`), у класса есть классный руководитель (`classes.teacher_id`).
Требование добавляет три сценария только для просмотра: расписание своего класса (ученик), личное
расписание по всем классам (учитель), полное расписание закреплённого класса (классный руководитель).
Создание и редактирование расписания в задачу не входят; критерий готовности № 6 — административная
часть работает без изменений.

## Решение

| Вопрос | Решение | Почему |
|---|---|---|
| Связь урока с учётной записью учителя (UC-02) | Необязательный FK `schedule_entries.teacher_id` → `users`; в форме урока — выбор учителя из списка; `teacher_name` остаётся для внешних преподавателей и как резервное отображение | Предусловие UC-02 — «уроки связаны с его учётной записью»; сопоставление по ФИО ненадёжно (дубликаты, переименования, опечатки) — BR-03 требует актуальных связей |
| Фильтры двух учительских сценариев | «Моё расписание» — по `schedule_entries.teacher_id`; «Расписание моего класса» — по `classes.teacher_id` | Разные связи: «ведёт уроки» и «закреплён за классом» |
| Правило UC-01 «только свой класс» | В кабинете раздел без выбора класса, класс берётся из `student_classes`; публичная страница `/schedule` остаётся без изменений | Публичный просмотр расписания гостями заявлен в исходном ТЗ; правило относится к личному разделу ученика |
| Время урока | В БД не хранится: справочник звонков — константа `BELL_TIMES` (уроки 1–12) в `src/lib/schedule.ts` | В существующих данных времени нет; дублировать интервал в каждой строке не нужно (BR-02) |
| Общий вид | Компонент `src/components/schedule-view.tsx` + группировка `groupByDay` в `src/lib/schedule.ts`; публичная страница переведена на них | Одинаковые группировка, сортировка и внешний вид во всех разделах |
| UC-03 без назначения | Ссылка в панели скрыта; прямой запрос `/teacher/my-class` → 404 | BR-04: проверка на сервере; согласуется с правилом «чужой ресурс = 404» |
| Ошибка загрузки (A3/A2) | Запрос в `try/catch`, пользователю — «Не удалось получить расписание. Попробуйте ещё раз позже.» | UC требуют явной обработки ошибки загрузки данных |

## Последствия

- Миграция `20261105120000_schedule_teacher_id`: nullable-столбец, FK с `ON DELETE SET NULL`, индекс.
  Существующие строки не меняются, копирование расписания переносит связь; критерий № 6 соблюдён.
- Урок без выбранного учителя в «Моё расписание» не попадает — при наполнении расписания админ выбирает
  учителя из списка (отражено в `docs/manual-testing.md`).
- Интервалы звонков — заглушка, перед эксплуатацией уточнить у школы (как и данные в `src/lib/school.ts`).
- Критерии готовности закрываются секцией «Расписание на неделю» в кабинете ученика (UC-01) и на
  панели учителя (UC-02), а также страницей `/teacher/my-class` (UC-03); права —
  `requireUser(["student"|"teacher"])`, изменение расписания этими ролями отсутствует (BR-06).
- Уточнение (2026-11-05): недельная сетка встраивается прямо в страницу личного кабинета и панель
  учителя с подсветкой текущего дня; отдельные страницы `/cabinet/schedule` и `/teacher/schedule`
  удалены как дубликаты; `/teacher/my-class` осталась отдельной страницей (селектор закреплённых
  классов). Ошибка загрузки в секциях обрабатывается так же, как описано выше.
- Уточнение 2 (2026-11-05): блок расписания оформлен по референсу заказчика — вкладки дней с датами
  («Пн, 20 окт») и список уроков выбранного дня (номер, время, предмет, учитель/класс, кабинет),
  навигация по неделям стрелками. Без клиентского JS: вкладки и недели — ссылки с URL-параметрами
  `week` (понедельник) и `day`. Данные остаются недельным шаблоном: даты вычисляются от выбранной
  недели, уроки повторяются; датированные уроки, замены и каникулы — возможное развитие вне объёма.
