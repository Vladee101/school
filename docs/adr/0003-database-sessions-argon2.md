# ADR 0003. Сессии в БД + cookie, пароли argon2

**Статус:** Принято

## Контекст
Вход по логину и паролю, без самостоятельной регистрации, с обязательной сменой временного пароля. Нужно уметь немедленно
завершать сессии (деактивация, сброс пароля). Использовать стороннего провайдера или JWT избыточно.

## Решение
- Случайный токен (32 байта) в `httpOnly`, `sameSite=lax`, `secure` (в production) cookie `sid`, срок 7 дней.
- В таблице `sessions` хранится только SHA-256 токена: утечка БД не раскрывает рабочие токены.
- Пароли хэшируются argon2; при неизвестном логине выполняется проверка по заглушке-хэшу, чтобы время ответа не выдавало
  существование пользователя; сообщение об ошибке одинаково для неверного пароля, неизвестного и неактивного пользователя.
- Смена пароля и деактивация удаляют все сессии пользователя; смена пароля сбрасывает `must_change_password`.
- Политика пароля: 8–128 символов, минимум одна буква и одна цифра.

## Последствия
- Каждый запрос с сессией делает чтение из БД (допустимо для данного масштаба).
- CSRF для server actions закрывается встроенной проверкой Origin в Next.js плюс `sameSite=lax`.
- Роль и активность пользователя перечитываются из БД на каждый запрос, поэтому отключение действует сразу.
