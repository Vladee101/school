# ADR 0005. Фиксированный тест Климова, неизменяемые результаты, подсчёт на сервере

**Статус:** Принято

## Контекст
По ТЗ вопросы и ключ ДДО Климова фиксированы, администратор их не редактирует, незавершённое прохождение не сохраняется,
сохранённый результат не меняется и не пересчитывается, при равных максимумах показываются все типы.

## Решение
- Ключ и подсчёт: [src/lib/klimov.ts](../../src/lib/klimov.ts), тексты 20 пар: [src/lib/klimov-questions.ts](../../src/lib/klimov-questions.ts)
  (источник `docs/klimov_original_questions.html`). Сид записывает их в БД.
- Состояние прохождения живёт только в браузере; при закрытии страницы браузер предупреждает о потере.
- Баллы считает сервер ([submitTest](../../src/app/cabinet/test/actions.ts)), присланные клиентом значения не используются.
  Результат, 20 ответов и доминирующие типы создаются одной вложенной операцией Prisma (атомарно).
- Сумма шкал = 20 защищена `CHECK` в БД; редактирующих действий для результатов нет ни у кого.
- Повторное прохождение создаёт новый результат; в сводке учителя используется последний.

## Исправление ключа
В исходной версии ТЗ вопрос 15 был указан наоборот. Принят ключ из обновлённого ТЗ и оригинального опросника:
15А → «Человек — художественный образ», 15Б → «Человек — знаковая система». `docs/tz.html` содержит старый ключ и
устарел, актуален `docs/TZ_updated.html`.

## Последствия
- Менять методику можно только правкой кода и сида, без интерфейса (так и задумано ТЗ).
- Обновление страницы во время теста сбрасывает ответы (ожидаемое поведение по ТЗ 3.3).
- Ключ покрыт модульными тестами: 20 вопросов, по 8 вхождений на шкалу, сумма 20, равные максимумы.
