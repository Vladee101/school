# ADR 0009. Отправка форм через onSubmit, блокировка до гидратации, подсветка полей

**Статус:** Принято

## Контекст
React 19 сбрасывает значения неуправляемых полей после завершения `<form action={serverAction}>`: при ошибке валидации
пользователь терял всё введённое. Кроме того, при форме с обработчиком `onSubmit` ранний клик (до загрузки скриптов)
отправляет форму обычным GET-запросом, и значения, **в том числе пароль**, попадают в адресную строку и историю браузера.
Это обнаружено при проверке формы входа.

## Решение
- Формы с ошибками и подсказками ([ActionForm](../../src/components/action-form.tsx), форма входа, смена пароля, тест)
  отправляются через `onSubmit` + `startTransition(() => action(formData))`, поэтому введённые значения сохраняются.
- Кнопка отправки отключена, пока страница не гидратирована ([useHydrated](../../src/components/use-hydrated.ts)), и у форм задан
  `method="post"`: преждевременная отправка невозможна, а данные не попадают в URL.
- Server action возвращает `{ error, field }`; `field` (имя поля или несколько через запятую) подсвечивается
  атрибутом `aria-invalid`, получает фокус, подсветка снимается при правке ([use-field-highlight](../../src/components/use-field-highlight.ts)).
  Для валидации Zod имя поля берётся из пути ошибки (`zodFail`, [form-state](../../src/lib/form-state.ts)).
- Стили: красная рамка и фон для `aria-invalid`, синяя рамка и подсветка подсказки при фокусе ([globals.css](../../src/app/globals.css)).

## Последствия
- Новые формы с проверкой на сервере следует делать через `ActionForm`, а не `<form action>`.
- Простые формы без ошибок и данных (выход, удаление, публикация) остаются на `<form action={serverAction}>`: они
  работают и без JavaScript.
- Без JavaScript формы с `ActionForm` не отправляются (кнопка заблокирована); для закрытой части сайта это приемлемо.
