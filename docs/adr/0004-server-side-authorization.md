# ADR 0004. Авторизация на сервере через слой доступа к данным

**Статус:** Принято

## Контекст
ТЗ требует проверять права на сервере, а не скрытием элементов интерфейса. В Next.js `proxy` (бывший middleware) и layout
не являются полноценной авторизацией: layout не перерисовывается при навигации внутри раздела, `proxy` видит только cookie.

## Решение
- [src/lib/dal.ts](../../src/lib/dal.ts): `requireUser(roles)` читает сессию, перенаправляет гостя на `/login`, пользователя
  с временным паролем на `/change-password`, пользователя не той роли в его раздел. Вызывается в каждой странице и каждом
  server action/route handler (`requireAdmin()` для админки).
- [src/proxy.ts](../../src/proxy.ts) только быстро отправляет на вход при отсутствии cookie (оптимистичная проверка).
- Ограничение по данным делается самим запросом: ученик видит результаты с `studentId = текущий`, учитель только классы с
  `teacherId = текущий` ([src/lib/teacher-access.ts](../../src/lib/teacher-access.ts)). Чужой ресурс отвечает 404, неотличимо
  от несуществующего.
- Администратору доступен просмотр результатов всех классов теми же страницами, что у учителя (в матрице ТЗ у админа «Да»).

## Последствия
- Новая страница или action без `requireUser` будет открыта: это нужно проверять на ревью.
- Учитель не имеет изменяющих действий вообще: запрет изменения результатов обеспечен отсутствием кода, а не условием.
