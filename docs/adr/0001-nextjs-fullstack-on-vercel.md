# ADR 0001. Next.js как единое full-stack приложение на Vercel

**Статус:** Принято

## Контекст
Нужен сайт на ~25 экранов (публичная часть, три роли, CRUD в админке, тест) с бесплатным постоянным хостингом.
Рассматривались: отдельные React и Node API; Django; Next.js. В процессе появился вопрос о Django.

Бесплатные альтернативы Vercel имеют ограничения: Render засыпает и удаляет бесплатную БД через 30 дней, Railway платный
после пробного кредита. Django на Vercel возможен, но требует обходов (файлы, статика, миграции).

## Решение
Один проект на Next.js (App Router) и TypeScript, развёртывание на Vercel. Серверная логика в server actions и серверных
компонентах, один route handler (`/api/blob/upload`).

## Последствия
- Один репозиторий и один деплой, общий язык и схемы валидации (Zod) для форм и сервера.
- Нет отдельного API, значит нет CORS и двойной сериализации.
- Режим `cacheComponents` из шаблона отключён: страницы с сессией динамические, обязательные `Suspense`-границы на каждую
  страницу давали лишнюю сложность без выигрыша для CRUD-сайта.
- Serverless: нет постоянной файловой системы (см. ADR 0006), для БД нужен pooled-адрес (ADR 0002).
- Отказ от Django: готовая админка сократила бы работу, но потребовала бы обходов на Vercel; решение подтверждено заказчиком.
