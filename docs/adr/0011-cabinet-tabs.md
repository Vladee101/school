# 0011. Вкладки «Расписание» и «Тестирование» в кабинете ученика и на панели учителя

Дата: 2026-11-10. Источник требования: заказчик — в личном кабинете ученика и учителя две вкладки:
«Расписание» (по умолчанию, активная выделена рамкой) и «Тестирование» (профориентационный тест
и история результатов).

## Контекст

Кабинет ученика (`/cabinet`) и панель учителя (`/teacher`) показывали расписание и материалы
тестирования одним списком. Требование разделяет их на две вкладки; по умолчанию открыта
вкладка расписания.

## Решение

| Вопрос | Решение | Почему |
|---|---|---|
| Механика вкладок | Ссылки с URL-параметром `tab`: без параметра — «Расписание», `tab=testing` — «Тестирование»; компонент `src/components/cabinet-tabs.tsx`, активная вкладка выделена рамкой | Как вкладки дней в `ScheduleView` (ADR-0010): без клиентского JS, вкладка делится ссылкой, прямые заходы по URL работают; произвольные значения `tab` трактуются как «расписание» |
| «Тестирование» ученика | Карточки «Профориентационный тест» и «История результатов» — прежние секции кабинета | Прямо соответствует формулировке требования |
| «Тестирование» учителя | Карточки классов со сводкой по тесту — прежний низ панели | Личный тест у учителя отсутствует (проходить тест могут только ученики); «тестирование» учителя — результаты его классов |
| Вкладки у администратора | Не показываются; `/teacher` для администратора остаётся списком классов | У администратора на этой странице расписания нет; требование касается ученика и учителя |

## Последствия

- Запрос расписания учителя выполняется только на вкладке расписания (`tab === "schedule"`); запрос
  классов остаётся безусловным — нужен шапке для ссылки «Расписание моего класса».
- Ссылки дней/недель внутри `ScheduleView` не содержат `tab` и ведут на вкладку расписания — она и есть
  вкладка по умолчанию; в `ScheduleView` изменений нет.
- Прямые заходы на `/cabinet?tab=testing` и `/teacher?tab=testing` работают; содержимое вкладок
  полностью на сервере, клиентского JS вкладки не добавляют.
