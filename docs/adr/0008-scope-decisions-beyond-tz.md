# ADR 0008. Решения по пробелам и неоднозначностям ТЗ

**Статус:** Принято

ТЗ не описывало некоторые детали. Принятые решения:

| Вопрос | Решение | Почему |
|---|---|---|
| Кто заполняет расписание | Администратор: добавление уроков, удаление, копирование расписания другого класса | В ТЗ нет управления расписанием, без него страница пуста; подтверждено заказчиком |
| Ученик и класс | Ученик состоит ровно в одном классе (`student_classes.student_id` — первичный ключ) | В ТЗ текст («один класс») и таблица (N:M с годом) противоречили друг другу |
| Смена роли | Нельзя после создания | У учителя бывают классы, у ученика результаты; безопаснее создать новую учётную запись |
| Удаление пользователей | Только пользователя без результатов тестов и не себя; классы удалять нельзя. Остальным доступна деактивация | Сохраняет историю результатов; классы удаляемого учителя остаются без учителя |
| Просмотр результатов администратором | Те же страницы, что у учителя, по всем классам, без права изменения | В матрице прав ТЗ у администратора «Да» |
| Первый администратор | Создаётся сидом из `ADMIN_LOGIN` / `ADMIN_PASSWORD`, при первом входе обязательна смена пароля | В ТЗ «по процедуре развёртывания» не описана |
| Формат новостей | Обычный текст с переносами строк | Исключает XSS, достаточно для MVP |
| Дата публикации | Задаётся при публикации (по умолчанию сегодня), редактируется; новость с датой в будущем скрыта | Сортировка по `published_at` по ТЗ |
| Пагинация | Новости по 10 на странице | В ТЗ не указана, список может расти |
| Данные школы | Хранятся в коде ([src/lib/school.ts](../../src/lib/school.ts)), не в БД | ТЗ: «статическая информация» |
| Лимит входа | См. ADR 0007 | Защита от подбора пароля |
| Категории документов | Выпадающий список из пяти стандартных категорий и уже использованных, плюс пункт «Другая категория…» ([src/lib/doc-categories.ts](../../src/lib/doc-categories.ts)) | В ТЗ категория просто строка; список защищает от опечаток и дублей |
| Размер PDF | До 20 МБ, имя файла в хранилище случайное | Лимита в ТЗ нет; случайное имя исключает проблемы с кириллицей в путях |
| Рекомендации по профессиям | У профессии кроме названия и описания есть «полезные школьные предметы» и «как познакомиться с профессией»; показываются карточкой в результате | Формат утверждён заказчиком; в ТЗ были только название, описание, тип |
| Стартовое наполнение справочника | Скрипт `npm run db:seed-professions`: 5 описаний типов и 40 профессий, ничего не перезаписывает | Без данных результат теста выглядел пустым; тексты учебные, их проверяет заказчик |
| Расписание | Уроки добавляются по одному, есть копирование расписания класса | Массовый ввод в MVP не входит |
