# Ручные проверки

Чек-лист для приёмки на развёрнутом сайте. Нумерация критериев (AC) соответствует разделу 16 ТЗ.
Отметка ✅ в колонке «Авто» означает, что поведение дополнительно покрыто модульными тестами (`npm test`).

## 0. Подготовка

1. Войдите администратором (`ADMIN_LOGIN`), задайте постоянный пароль.
2. Создайте тестовые данные (все названия с префиксом `QA`, чтобы потом удалить или отключить):
   - классы `QA-9А` и `QA-9Б`, учебный год `2026/2027`;
   - учителя `qa_teacher1` (класс `QA-9А`) и `qa_teacher2` (класс `QA-9Б`);
   - ученики `qa_student1`, `qa_student2` (в `QA-9А`), `qa_student3` (в `QA-9Б`);
   - временный пароль у всех, например `Test2026x`.
3. Опубликуйте одну новость и один PDF, добавьте одну новость-черновик и один документ-черновик.
4. Добавьте 2–3 урока классу `QA-9А` (раздел «Расписание класса»).
5. Добавьте хотя бы одну профессию к типу «Человек — природа».

Тесты ниже выполняйте в разных браузерах или в режиме инкогнито, чтобы роли не смешивались.

## 7. Целостность данных (НФТ 15.4)

Выполняется в консоли БД (Neon) под руководством разработчика:

```sql
-- у каждого результата 20 ответов
SELECT r.id, COUNT(a.id) FROM test_results r LEFT JOIN answers a ON a.result_id = r.id
GROUP BY r.id HAVING COUNT(a.id) <> 20;          -- ожидается 0 строк

-- сумма шкал равна 20
SELECT id FROM test_results
WHERE score_chp + score_cht + score_chch + score_chz + score_chho <> 20;   -- 0 строк

-- у каждого результата есть хотя бы один доминирующий тип
SELECT r.id FROM test_results r LEFT JOIN result_dominant_types d ON d.result_id = r.id
WHERE d.result_id IS NULL;                        -- 0 строк
```

Попытка вручную записать результат с суммой, не равной 20, должна быть отклонена ограничением `test_results_scores_valid`.

## 8. Уборка после проверок

Отключите тестовые учётные записи (`QA…`) в админке, удалите тестовые новости и документы. Классы и
результаты удалять нельзя, их можно оставить или очистить в консоли БД.
